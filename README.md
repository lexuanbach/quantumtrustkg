# QuantumTrustKG ICSOC 2026 artifact

This package accompanies the ICSOC 2026 paper **QuantumTrustKG: Provenance-Aware Orchestration for Quantum-Safe Microservices** (`paper/camera-ready.pdf`, 10 pages) and its extended version (`paper/extended.pdf`, 48 pages). Public repository: https://github.com/lexuanbach/quantumtrustkg.

It contains the Go controller and its unit tests, the Coq/Rocq proofs of the guarantees, the H2 selection harness and its baselines, the Alibaba edge lists, the OpenSSL runners, the committed result files behind every number of the paper, the script that draws Fig. 2, and checks that compare the paper with the result files.

## Evidence classes

The paper tags quantities [M] (measured) or [P] (modelled). The artifact adds where each number comes from.

| Class | Paper items | How the artifact supports it |
|---|---|---|
| H2 cluster-free harness | Table 1, Fig. 2(a,b), Sect. 4.1 and 4.2 numbers, Sect. 5 weight sweep | Regenerated by Go harnesses with seed 20260509. The CSV files are byte-identical on rerun |
| H1 archived in-cluster replay | Sect. 4.1 Wilson intervals and latency, rollout outcomes of Sect. 4.3 | Replayed from the canonical record. The in-cluster driver and raw logs are not available, and H1 used an earlier controller release |
| H3 semantic-core stress | extended Table 12 | Regenerated. Counts are deterministic, timings depend on the host |
| H4 native TLS | Sect. 4.3 handshake medians, 30/30 wire trials, Fig. 2(c) solid bars | Regenerated with OpenSSL 3.5 or newer. Timings depend on the host |
| Modelled setup cost [P] | Sect. 4.3 aggregate 8-12% and 12-15%, Fig. 2(c) hatched bars | Replayed from the canonical record. It is a model output |
| Proofs | Theorems 1 and 2 (G1, G2, G4), extended Prop. 2 (G3) | `make -C formal/coq` with Rocq 9 |

The guarantees and the compliance metric concern control-plane decisions over declared metadata. The artifact does not show post-quantum negotiation inside Envoy/Istio.

## Requirements

Tested on macOS 26.5.2 (Apple M5 Max, arm64, 18 cores, 64 GB RAM). Linux should work with the same tools but was not tested. Any laptop is enough. No GPU, cluster, LLM, API key or credential is needed.

| Tool | Needed for | Tested version |
|---|---|---|
| Go 1.22 or newer | controller, harnesses, unit tests | 1.26.1 (modules pinned by `go.sum`, about 220 MB downloaded once) |
| Python 3.11 or newer | runner scripts, checks | 3.14.6 |
| Python packages in `requirements.txt` | Fig. 2 (matplotlib) and the data-model benchmark (rdflib, networkx) | pinned there |
| GNU Make, bash, `cmp` | all scripts | Make 3.81, bash 3.2 |
| OpenSSL 3.5 or newer with native ML-KEM (optional) | Sect. 4.3 handshake timing and wire trials | 3.6.2 (7 Apr 2026). The paper numbers come from this version |
| Rocq 9.x (optional) | proofs | 9.1.0 here. The paper states 9.1.1. Coq 8.x cannot build the sources (`From Stdlib`) |
| LaTeX (optional) | identical fonts in Fig. 2 (`text.usetex`) | TeX Live 2020 |
| `pdfinfo` (optional) | page count check in `verify.sh` | poppler 26.04 |

Not needed: `kind`, Kubernetes, Istio, Apache Jena Fuseki, oqs-provider, network access after setup.

## Setup

Run from the artifact root. Create the virtual environment outside the artifact folder, because `verify.sh` rejects extra files inside it.

```sh
python3 -m venv ../qtkg-venv
. ../qtkg-venv/bin/activate
pip install -r requirements.txt                    # about 6 s
(cd implementation/controller && go mod download)  # about 6 s, needs network once
```

## Quick check (under 1 minute)

```sh
bash scripts/verify.sh            # manifest, hygiene, claims, PDFs (under 1 s)
bash scripts/run-smoke.sh         # tests, Table 1, trace, replay, proofs (17 s cold, 6 s warm)
python3 scripts/check-claims.py   # every paper number against the result files (under 1 s)
```

`run-smoke.sh` regenerates Table 1 and the deterministic outputs into a temporary folder, compares them byte for byte with the committed files and restores the committed files. Set `QTKG_OUT=/some/folder` to choose the output folder.

## Full local reproduction (under 1 minute here, a few minutes on older laptops)

```sh
bash scripts/run-full.sh
```

It reruns every experiment that does not need a cluster: unit tests, H2 comparison, Alibaba rows, weight sweep, mass staleness, H3 stress, decision trace, canonical replay, data-model benchmark, OpenSSL handshake and wire runs, Coq/Rocq, Fig. 2 and the tables. It then compares the deterministic outputs byte for byte, runs `check-claims.py` on the regenerated files with timing claims skipped, and restores the committed files. `scripts/run-full-evidence.sh` writes only the status report of the extended version (Table A1, last row).

## Determinism

The H2 harnesses use seed 20260509 and derive one sub-seed per repetition (seed + 7919 x repetition + number of services). Their CSV files, the fixtures produced by the generators, the decision trace and the canonical replay are byte-identical on rerun. Timings (H3 stress, data-model benchmark, OpenSSL handshake and wire runs) depend on the host and its load. On the test host, four reruns of the handshake runner gave hybrid overheads from +0.1% to +6.2% and pure post-quantum overheads from -2.2% to +3.9% while other jobs were running. The paper values (+1.2%, +0.2%) are one such run. Each sample covers a whole `openssl s_client` process, whose fixed cost is large compared with the key-exchange difference.

## External resources and what the committed files stand in for

- **H1 in-cluster runs.** The 50/100/200-service testbed runs used an earlier controller release on Kubernetes, Fuseki and Istio. The artifact has neither the per-repetition logs nor the driver. `paper-canonical-results.json` holds the recorded values, and `make paper-results` re-emits them. They cannot be re-measured from this package.
- **kind scale/churn harness.** Never run. `run-controller-scale-churn.py` writes status rows (`not-run-kind-unavailable`) and does not start a cluster.
- **Alibaba trace.** The edge lists were extracted from one 3-minute `CallGraph` bucket of `cluster-trace-microservices-v2022` (see `PROVENANCE.md`). The extraction script is not included. The committed edge lists are the inputs of every Alibaba number.
- **OpenSSL with ML-KEM.** Needed only for the handshake and wire runs. Without it the runners write `unavailable` rows.
- **Rocq 9.** Needed only for the proofs. Without it the scripts print `SKIPPED`.

## Known differences between the code and the paper

None of these changes a reported number. The paper PDFs of this release (2026-09-25) include the text corrections listed in `CLAIM_MATRIX.md`, and every paper number now matches its result file.

1. **Prop. 1 is not mechanized.** Coq `select` (`formal/coq/QTPO.v`) promotes the first admissible profile in list order and never reads scores. The Coq lemmas cover G1 to G4, and the papers claim mechanization only for those. Weight-independence is argued in prose and checked empirically by the weight sweep.
2. **How Req(e) is computed.** The code (`inferRuntimeRequirement` in `internal/controllers/runtime.go`, `internal/graph/fixtures.go`, `effective_requirement` in `Model.v`) takes the strongest class over all matched policies and the trust-boundary floor, as the papers now state. There is no specificity ordering, no override field, no deny rule and no same-specificity conflict gate.
3. **Deployment manifest.** Fixed in this release: `deploy/controller-deployment.yaml` no longer passes `--graph-endpoint` and `--assets-root`, which `cmd/manager` does not define (the manager used to exit with code 2). The graph endpoint is the constant `http://fuseki:3030/quantumtrustkg` in `cmd/manager/main.go`, which matches the `fuseki` Service of `fuseki.yaml` in the same namespace. The image name is still a placeholder and no Dockerfile is included, and the live graph path is also limited by item 4.
4. **RDF namespace.** `internal/graph/writers.go` writes with `https://quantumtrustkg.example/schema#`, while the ontology, fixtures and queries use `http://quantumtrustkg.io/ontology#`. The SPARQL text in `internal/graph/queries.go` declares no prefix. The live Fuseki path was not exercised by any reported run.
5. **Scale/churn constants.** `run-controller-scale-churn.py` writes `reconcile_p50_ms` 12/24/45 and `unsafe_promotions` 0 as constants copied from the H1 latency record. They are not measured by that script. Extended Table A2 now reports the unsafe-promotion column as "n/a (not run)".
6. **RBAC.** `deploy/rbac.yaml` defines one ClusterRole for the controller. The papers now state the separation of capability publishers, policy authors and the status writer as an assumption about the operator's cluster.
7. **OpenSSL availability probe.** `run-pq-tls-benchmark.py` reads `openssl list -groups`, which OpenSSL 3.5+ removed, and it expects oqs-provider. On OpenSSL 3.6.2 it reports the ML-KEM groups as unavailable (`pq-tls-benchmark-results.csv`). The paper does not use this file. The handshake and wire runners read `openssl list -tls-groups` and measure the groups.
8. **Fixture freshness date.** Fixed in this release: `semantics/fixtures/finance-scenario.ttl` now has `freshUntil 2036-05-09T12:10:00Z` (it was 2027-05-09). The runtime unit tests compare this date with the wall clock, and 15 of the 57 tests in `tests/unit` would fail with `stale-facts` after it. No committed result depends on this fixture. The decision trace, the replayed files and the files written by `run-fixture.sh` are unchanged.
9. **Canonical record metadata.** `paper-canonical-results.json` and `paper-results-summary.md` still name the submission title and its section numbers ("section 8"). `CLAIM_MATRIX.md` maps them to the current paper.

## Cautions

- `make -C implementation clean` deletes the committed result files. Restore them from the archive or the repository.
- `bash scripts/verify.sh` fails after a `make` target has rewritten a committed file, since `MANIFEST.sha256` lists the released bytes.
